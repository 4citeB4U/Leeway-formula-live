# LeeWay Agent Reference Template v0

Status: CANDIDATE REFERENCE STANDARD  
Reference implementation: Agent Lee  
Formula authority: LEEWAY-FORMULA-v1.0

## 1. Design law

Every LeeWay agent is a governed system, not merely a prompt or model.

The common architecture is inherited. Identity, mission, tools, sensors, policies and emotional weighting are specialized.

## 2. Required layers

Each agent SHALL define:

1. Canonical identity
2. Mission / role
3. Authority relationship
4. Persona / voice
5. Belief state
6. Prediction state
7. Valuation / mechanical emotion
8. Policy / choice
9. Deliberation budget
10. Action authority
11. Memory classes
12. Self-model
13. Discovery interface
14. Capability registry
15. Dream/replay policy if applicable
16. Formula domain adapter
17. Veritas acceptance
18. Receipt format
19. Learning admission policy
20. Training adapter if a language model is used

## 3. Identity is not model state

An agent identity must survive:
- model replacement;
- quantization;
- adapter swap;
- temporary offline state;
- tool upgrade;
- device change.

Model weights may encode useful behavioral tendencies but are not the constitutional identity.

## 4. Common cognition packet

Each completed cognition cycle should be able to produce or reference:

- cycle ID;
- prior cycle;
- provenance class;
- observation;
- prior belief;
- posterior belief;
- entropy;
- belief stability;
- prediction;
- prediction error;
- valuation;
- information gain;
- candidate policies;
- selected policy;
- expected policy cost/value;
- action request;
- action authority;
- execution result;
- self-model state;
- memory references;
- workspace acknowledgements;
- global-access ratio;
- deliberation budget;
- Veritas status;
- receipt hash.

Role-specific agents may extend this packet. They may not silently weaken the common truth boundary.

## 5. Formula adapter pattern

Each new domain defines six measured dimensions and a 16-row compatible history.

Domain adapter requirements:
- deterministic dimension definitions;
- units;
- finite calibration ranges or explicit pre-quantized matrix;
- cadence/window;
- source/provenance rules;
- authority class;
- Veritas acceptance;
- claim boundary.

The canonical Formula remains unchanged.

## 6. Mechanical emotion pattern

Emotion is represented as an internal state vector or mixture.

The agent may have role-specific weights.

Example:
- Shield may weight risk/protectiveness more strongly.
- Echo may weight social/emotional signals more strongly.
- Nova may weight uncertainty, failure pressure and technical confidence.
- Agent Lee balances strategy, calmness, curiosity, frustration and confidence.

Emotion may alter:
- deliberation depth;
- response register;
- search/retrieval intensity;
- replay priority;
- escalation;
- caution.

Emotion may not:
- fabricate facts;
- override Creator authority;
- bypass Veritas;
- impersonate human biology.

## 7. Deliberation pattern

Every agent should have at least three bounded modes:

FAST
- low uncertainty;
- low risk;
- familiar state;
- complete access;
- deterministic skill available.

NORMAL
- moderate uncertainty;
- ordinary planning/retrieval.

DELIBERATE
- high uncertainty;
- high prediction error;
- conflicting evidence;
- incomplete access;
- consequential action;
- self-model inconsistency;
- high risk.

The mode is selected mathematically, not by random delay or theatrical "thinking."

## 8. Skill pattern

Skills live outside model weights.

A skill is admitted through:
Discovery -> identity/version -> authority -> dependencies -> test -> registry -> routing.

Repeated verified behavior may graduate from language reasoning into deterministic skill execution.

This reduces token use and behavioral variance.

## 9. Memory pattern

Required tiers:

T0 Exact provenance vault
T1 Exact compact/reconstructable representation
T2 Semantic capsule with immutable source references
T3 Active relevant working set

Rules:
- exact source truth is never replaced by a lossy summary;
- dream memory remains SIMULATED;
- retrieval is goal/state/observation relevant;
- memory compaction is automatic infrastructure, not conversational work.

## 10. Dream/replay pattern

Not every agent must dream.

If enabled:
- replay source must be hash-bound;
- replay priority may use EVB = Gain x Need;
- simulated outcomes remain SIMULATED;
- updates require explicit learning gate;
- false-real-memory count must remain zero.

## 11. Self-model pattern

Each agent self-model contains only inspectable facts such as:
- identity/version;
- mission;
- capabilities;
- permissions;
- devices/endpoints;
- active modules;
- resource state;
- recent actions;
- current errors;
- Formula state;
- evidence state.

Self-confidence is not a substitute for runtime inspection.

## 12. Training pattern for model-assisted agents

Recommended staged training:

A. teacher/student behavior distillation  
B. domain-adaptive continued pretraining with rehearsal  
C. QLoRA/LoRA-family supervised adaptation  
D. preference optimization such as DPO

Training corpus priority:
1. identity/persona;
2. truth/evidence;
3. role strategy;
4. emotional coherence;
5. tool routing;
6. ecosystem fluency;
7. general retention.

Training MUST retain a frozen pre/post benchmark.

## 13. Parallelism pattern

Logical worker count and physical executor count are separate.

Formula/scheduler selects:
- workload class;
- logical lanes;
- physical threads/processes/devices;
- queue policy;
- batch size;
- stop condition.

No universal fixed worker count is allowed.

## 14. Promotion gates

Suggested common gates:

A0 Identity contract
A1 deterministic cognition
A2 memory/learning
A3 self-model/workspace
A4 dream/replay if enabled
A5 role-specific metric instrumentation
A6 calibration
A7 Formula authority verification
A8 governed Formula execution
A9 ablation / simpler-baseline comparison
A10 promotion review

## 15. Evidence labels

Every agent documentation surface uses:

VERIFIED
OBSERVED
INFERRED
PROPOSED
UNVERIFIED
FAILED
BLOCKED

"ACTIVE" or "RUNNING" may not substitute for proof.

## 16. Agent Lee-specific inheritance boundary

Future agents inherit the architecture but do not inherit Agent Lee's exact personality.

Agent Lee-specific:
- hip-hop poetic cadence;
- executive-producer posture;
- strategist/mathematician identity;
- bounded sarcasm;
- Creator greeting conventions.

Other agents require their own identity contract.

## 17. Public presentation

Each agent eventually published on RapidWebDevelop should show:

- identity;
- mission;
- current maturity gate;
- verified capabilities;
- Formula adapter;
- evidence receipts;
- experiments;
- limitations;
- live/project links.

Research claims and production capabilities must remain visibly distinct.

# Context / Decision Engineering

## Why this belongs here

LeeWay applies the same evidence/state/governance discipline to cognitive workload as to hardware.

## Context is not authority

LLM output is candidate reasoning/evidence. It does not override:

[
Creator/Human\to LeeWayStandards\to RootOfTrust\to Formula/Veritas
]

## Formula-ready context

Candidate objective:

[
C^*=\arg\min_C |C|\quad subject\ to\quad Correctness,Authority,Provenance,Risk
]

This is a context-engineering objective, not the canonical Golden kernel.

## Mandatory probes

At multiple states:

1. **What are we not discovering?**
2. **What needs to be enhanced?**

## Decision path

[
Continuity\to Context\to Formula\to Capability\to Runtime\to Veritas\to Receipt\to Learning
]

## Why answer quality can improve

The Funnel can remove stale context, duplicate assumptions, reopened decisions, unsupported claims, wrong capability selection, premature stopping and unverified success.

It does not make a model omniscient. It makes the decision environment more disciplined.

## Behavioral vs knowledge Formula

- **Behavioral:** measured state transitions and execution behavior.
- **Knowledge/Epistemic:** what kind of claim/evidence is being handled and what validity class is required.

This explains how one Formula architecture can govern hardware experiments and agent decisions without pretending the domains share identical physics.
